================================================================================
RISC-V (RV32IMA) 自作CPU向け MMU・キャッシュ・PTW 設計議論まとめ
================================================================================

1. MMUの基本的なハードウェア構成
--------------------------------------------------------------------------------
MMU（Memory Management Unit）は以下のハードウェア要素で構成される。
・TLB（Translation Lookaside Buffer）：仮想アドレスと物理アドレスの対応を保持する高速な連想メモリ（CAM/レジスタ）。
・PTW（Page Table Walker）：TLBミス時にメモリ上の多段ページテーブルを辿るハードウェアステートマシン。
・制御・ベースレジスタ：ページテーブルの先頭アドレスや有効化を管理（RISC-Vでは satp CSR）。
・権限・属性チェック回路：R/W/X/Uなどの権限を検証し、違反時はページフォールト例外を通知。
・キャッシュ・バス制御インターフェース：物理アドレスと属性に応じてキャッシュやバスへ振り分け。

2. RISC-VにおけるMMU構成（Sv32 / Sv39 / Sv48 / Sv57）
--------------------------------------------------------------------------------
・satpレジスタ：MODE（変換方式）、ASID（プロセスID）、PPN（ルートページテーブル物理ページ番号）を保持。
・ITLB / DTLB分離構成：命令フェッチ用のITLBとデータアクセス用のDTLBを独立配置。
・Sv32（RV32IMA用）：32ビット仮想アドレス → 34ビット物理アドレス。2段ページテーブル（10bit × 2）、4KiB基本ページ・4MiBメガページ対応。
・PMP（Physical Memory Protection）：MMUの後段に位置し、物理アドレス単位でアクセス保護を行う。

3. TLB・キャッシュ（I$ / D$）に必要なメモリ容量の目安（RV32IMA）
--------------------------------------------------------------------------------
(1) TLB（Sv32）の容量
・1エントリあたり約61ビット（タグ部31bit：VPN 20bit + ASID 9bit + Valid + Megapage / データ部30bit：PPN 22bit + フラグ 8bit）。
・16エントリ時：ITLB 約122B + DTLB 約122B = 合計 約244バイト（カバー範囲：命令64KB + データ64KB）。
・32エントリ時：ITLB 約244B + DTLB 約244B = 合計 約488バイト（カバー範囲：命令128KB + データ128KB）。
※ASIDを省略（コンテキストスイッチ時全フラッシュ）すれば1エントリ52ビットまで削減可能。

(2) キャッシュ（I$ / D$）の容量目安
・学習・小規模FPGA：I$ 512B〜2KB / D$ 512B〜2KB
・組み込みRTOS：I$ 4KB〜8KB / D$ 4KB〜8KB
・組み込みLinux（Sv32使用）：I$ 16KB〜32KB / D$ 16KB〜32KB
※C拡張（圧縮命令）がないRV32IMAはコードサイズが大きくなるため、I$を大きめに確保するのが有効。
※16KB（4ウェイ・ライン32B）の場合、データ16KB＋タグ・管理ビット約1.4KBで計約17.4KB。
※VIPT（Virtual Index, Physical Tag）でエイリアシングを防ぐには「キャッシュ容量 ÷ ウェイ数 <= 4KB（ページサイズ）」にする（例：4ウェイ×16KB）。

4. I/O（MMIO）に対するMMUとPMAの扱い
--------------------------------------------------------------------------------
・I/O専用のMMUは別途不要：RISC-VはMMIO方式のため、CPU内蔵の1つのMMU（DTLB/PTW）でRAMとI/Oの両方を変換・保護する。
  （DMAデバイスからのメモリアクセス保護がサーバー等で必要な場合のみ別途IOMMUが存在するが、自作RV32IMA規模では不要）
・PMA（Physical Memory Attributes）：MAステージ内でアドレス範囲から「RAM（Cacheable）」か「I/O（Uncacheable）」かを判別する回路はPMAの実装に相当する。
・処理順序（OS運用時）：「MMUでVA→PA変換・権限チェック」→「変換後のPAでPMA判定（RAM or I/O）」→「RAMならD$、I/OならD$をバイパスしてI/Oバスへ」。

5. 5段パイプライン（IF-ID-EX-MA-WB）でのタイミングと高速I/Oの両立
--------------------------------------------------------------------------------
・1サイクル完結の並列アーキテクチャ（I/Oレジスタが1サイクル以内に応答する前提）：
  MAステージ開始と同時に以下3つを並列実行する。
  (A) DTLB検索（VA[31:12] → PA[33:12]・権限チェック）
  (B) D$ SRAM先行リード（VA[11:0]使用・VIPT）
  (C) I/Oレジスタ先行リード（VA[11:0]使用）
・MAステージ後半でDTLB結果が確定したら、PMA判定を行いMUXでD$またはI/Oの値をWBへ出力。
・TLB登録時に「このエントリはI/O領域（is_io_entry）」という1ビットフラグを事前計算して持たせると、PMA判定の遅延をゼロにできる。
・注意点：ライトイネーブル（WE）やリード副作用のあるI/Oレジスタ（FIFO等）のリードイネーブルは、必ずMMU変換・権限OK確定後にアサートする。

6. PTW（ページテーブルウォーカー）の共有とバス接続
--------------------------------------------------------------------------------
・PTWは1つで十分：ITLBミスとDTLBミスをアービタで調停し、1つの共有PTW（ステートマシン）で処理する。
・同時ミス時の優先順位：デッドロック防止のため、必ず「DTLBミス（MAステージ側・古い命令）優先、空いていればITLBミス（IFステージ側）」とする。
・メインメモリバス接続：PTW専用の外部バスポートは不要。
  - パターンA（推奨）：CPU（MA）とD$の入り口の間にMUXを置いてPTWを接続。ページテーブルがD$にキャッシュされ高速化でき、外部バス変更も不要。
  - パターンB：既存のバスアービタ（I$, D$）の3ポート目としてPTWを追加。既存D$に手を入れたくない場合に有効。

7. A拡張（LR/SC命令）とPTWアクセスとの干渉回避
--------------------------------------------------------------------------------
lr.w〜sc.w間にITLBミスが発生し、共有PTWがD$経由でページテーブルを読みに行った際の干渉を防ぐ鉄則：
・LR/SCの予約管理（res_valid + 物理アドレス32bit）は、D$のキャッシュライン内ではなく独立したレジスタで保持する（PTWによるキャッシュライン追い出しで予約が消えるのを防ぐ）。
・PTWのメモリアクセスは「読み出し（Load）」のみであるため、他者（PTW）からのReadでは予約を解除しない仕様にする（Storeや外部スヌープ時のみ解除）。
・lr.w / sc.w 自体がDTLBミスした場合は、PTW完了・権限確定後に予約セットや条件判定を行う。
